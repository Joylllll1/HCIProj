## Context

上一版实现中，回复仍然内嵌在评论下方。用户反馈：
1. 回复卡片应该是独立的，与评论平级
2. 回复卡片应该支持继续回复其他回复（嵌套回复）
3. 回复的逻辑应该与评论一致：点赞、回复、举报

## Goals / Non-Goals

**Goals:**
- 回复卡片作为独立条目，与评论卡片平级显示在评论列表中
- 回复卡片下方可以继续回复，形成嵌套回复链
- 回复卡片与评论卡片使用相同的交互逻辑
- 回复卡片显示被回复内容引用（灰色背景）

**Non-Goals:**
- 不修改后端 API 结构
- 不修改现有回复数据结构
- 不涉及回复删除功能

## Decisions

### 数据结构设计

后端返回的数据结构保持不变（回复内嵌在评论中），前端将数据扁平化处理：

```javascript
// 后端返回结构（不变）
{
  comments: [
    {
      id: "comment1",
      content: "评论内容",
      replies: [
        { id: "reply1", content: "回复内容" },
        { id: "reply2", content: "回复reply1", parentReplyId: "reply1" }
      ]
    }
  ]
}

// 前端扁平化处理后的展示结构
comments: [
  { type: "comment", ... },
  { type: "reply", parentId: "comment1", ... },
  { type: "reply", parentId: "comment1", parentReplyId: "reply1", ... }
]
```

### 与评论卡片的差异

| 元素 | 评论卡片 | 回复卡片 |
|------|---------|---------|
| 头像 | person 图标 | person 图标 |
| 顶部 | 无 | 灰色引用背景（显示被回复内容） |
| 举报位置 | 右上角 | 右上角（与评论一致） |
| 操作按钮 | 点赞、回复 | 点赞、回复（与评论一致） |

### 交互逻辑

1. **点赞**: 与评论相同，使用 thumb-up 图标，点击切换点赞状态
2. **回复**: 点击"回复"按钮，弹出回复输入框（显示在被回复卡片正下方）
3. **举报**: 右上角举报按钮，点击弹出举报弹窗（与评论位置一致）

### 回复输入框

- 显示在被回复的回复卡片正下方
- 支持 emoji 表情选择
- 有取消按钮可关闭

## Risks / Trade-offs

- [风险] 回复列表扁平化后，原始的父子关系可能被破坏
  - 缓解：在 ReplyCard 中显示被回复内容的引用，保持上下文清晰
- [风险] 嵌套回复过多时，页面会变长
  - 缓解：被引用内容默认折叠超过2行，支持展开/收起
