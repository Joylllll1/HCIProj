## Context

当前回复功能与评论混在一起，用户点击"回复"时只是设置一个 `replyingTo` 状态，然后在评论输入框中显示"回复 xxx"。这种方式不够直观，回复内容也是作为子列表嵌入在父评论下方。

## Goals / Non-Goals

**Goals:**
- 回复卡片独立展示，不再作为子列表嵌入父评论
- 回复框显示在所回复评论/回复的**正下方**
- 回复卡片结构清晰：被回复内容引用 → 回复者 → 回复内容 → 操作按钮
- 回复输入框支持 emoji 和图片（与评论输入框功能一致）

**Non-Goals:**
- 不修改后端 API
- 不修改现有评论数据结构
- 不涉及评论/回复删除功能

## Decisions

### 整体布局设计

```
┌─────────────────────────────────────────────────────────┐
│ [评论卡片]                                              │
│ ┌──────────┬──────────────────────────────────────────┐ │
│ │  头像    │ Alice                          [举报]    │ │
│ │          │ 评论内容文字啦啦啦                        │ │
│ │          │ 刚刚 · [👍 点赞] · [回复]                  │ │
│ └──────────┴──────────────────────────────────────────┘ │
│                                                          │
│   ↓ 用户点击"回复"后，输入框出现在此处                   │
│   ┌─────────────────────────────────────────────────┐   │
│   │ 回复 Alice                                      │   │
│   │ ┌─────────────────────────────────────────────┐ │   │
│   │ │ [textarea]                                  │ │   │
│   │ └─────────────────────────────────────────────┘ │   │
│   │ [表情] [图片]                      [发送回复]    │   │
│   └─────────────────────────────────────────────────┘   │
│                                                          │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ [回复卡片 - 独立卡片，不嵌套]                        │ │
│ │                                                     │ │
│ │ Bob                                                │ │
│ │ 回复 Alice: 这是回复内容                            │ │
│ │ 刚刚 · [👍 5 赞] · [回复]                            │ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

### 回复卡片详细结构

```
┌─────────────────────────────────────────────────────────┐
│ ┌───────────────────────────────────────────────────┐ │
│ │ Alice:                                           │ │
│ │ 评论内容第一行...                                 │ │
│ │ 评论内容第二行...                                 │ │
│ │ [展开] (内容超过2行时显示)                        │ │
│ └───────────────────────────────────────────────────┘ │
│ 灰色背景 (#f5f5f5)，浅色边框，圆角                    │
│                                                      │
│ Bob                                    [举报按钮]     │
│ 回复 Alice: 这是回复的具体内容，可以很长              │
│ 刚刚 · [👍 5] · [回复]                                  │
│          ↑ 点赞(thumb-up)    ↑ 回复按钮                │
└─────────────────────────────────────────────────────────┘
```

### 被引用内容的展开/收起逻辑

- 内容默认显示最多 **2 行**
- 超过 2 行时，右下角显示 `[展开]` 按钮
- 点击展开后显示全部内容，按钮变为 `[收起]`

### 回复输入框位置与功能

- 点击评论或回复的"回复"按钮后，输入框出现在**该评论/回复的正下方**
- 自动滚动到输入框位置并聚焦
- 输入框功能与评论输入框一致：
  - 支持 emoji 表情选择
  - 支持图片上传
  - 有取消按钮可关闭
- **回复框不需要显示被回复内容引用**，因为输入框就在被回复内容的正下方

### 操作按钮说明

- **点赞按钮**: 显示为 `👍 X` 格式（使用 thumb-up 图标），点击切换点赞状态（红色/灰色）
- **回复按钮**: 显示为 `回复` 文字，点击展开回复输入框
- **举报按钮**: 右上角，点击弹出举报弹窗
- 按钮样式与其他评论交互保持一致

### 数据流

1. 用户点击评论的"回复" → 设置 `replyTarget = { targetType: 'comment'|'reply', targetId, authorName, content }`
2. 回复框插入到目标评论/回复的正下方
3. 用户输入回复内容（可添加 emoji、图片）
4. 点击"发送回复" → 调用 `onReply(targetId, content)` → API 创建回复
5. 回复以独立卡片形式出现在评论列表中
6. 回复输入框消失

## Risks / Trade-offs

- [风险] 回复列表不再与父评论在一起，可能影响阅读连续性
  - 缓解：回复卡片中包含被回复内容的引用，用户可以快速理解上下文
- [风险] 回复数量多时，页面会变长
  - 缓解：这是预期行为，保持信息完整性更重要
- [风险] 回复输入框在页面中间位置，可能被键盘遮挡（移动端）
  - 缓解：使用 `scrollIntoView` 滚动确保输入框可见
