## Context

公告页面（AnnouncementsPage）目前使用静态假数据和 props 传参，需要连接真实后端 API。后端 Event 模型和 API 已完成（add-event-audit），包括创建活动、获取已通过活动、审核流程等。本次改动主要在前端，将活动墙功能与后端对接。

### 现有代码基础

| 模块 | 状态 | 说明 |
|------|------|------|
| Event Model | ✅ 完成 | status: pending → approved/rejected/archived |
| 后端 API | ✅ 完成 | getPublicEvents, createEvent 等 |
| 前端 service | ✅ 完成 | eventService.js 已有 API 函数 |
| AnnouncementsPage | ⚠️ 需改造 | 使用假数据，需连接 API |
| eventStore | ⚠️ 需改造 | 已有基本结构，需完善 |

## Goals / Non-Goals

**Goals:**
- 活动墙展示已通过审核的活动
- 往期活动自动折叠
- 用户可提交活动申请
- 我的申请 Tab 查看提交状态

**Non-Goals:**
- 首页轮播展示
- 通知推送
- 活动报名/收藏/评论

## Decisions

### 1. 活动分类策略

**决策**: 前端根据 `time` 字段判断活动是否过期

- 未结束活动 (`time > now`): 展示在主区域
- 已结束活动 (`time <= now`): 展示在"往期活动"折叠区域

**理由**: 不需要后端新增状态，复用现有 `approved` 状态即可，简化逻辑。

### 2. 我的申请实现方式

**决策**: 新增 API `/api/events/my` 获取当前用户提交的活动

**理由**:
- 前端 Tab 切换，不跳转新页面
- 复用现有 UI 风格
- 需要后端新增一个接口

### 3. 页面结构

**决策**: 使用 Tab 切换"全部活动"和"我的申请"

```
┌─────────────────────────────────────────┐
│  校园公告 & 活动中心        [发布活动]   │
├─────────────────────────────────────────┤
│  [全部活动]  [我的申请]                  │
├─────────────────────────────────────────┤
│  [分类筛选: 全部 | 讲座 | 招聘 | ...]    │
├─────────────────────────────────────────┤
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌───────────┐ │
│  │活动1│ │活动2│ │活动3│ │ 发起新活动 │ │
│  └─────┘ └─────┘ └─────┘ └───────────┘ │
│                                         │
│  ▶ 往期活动 (3)                         │
│  ┌─────┐ ┌─────┐ ┌─────┐               │
│  │过期1│ │过期2│ │过期3│               │
│  └─────┘ └─────┘ └─────┘               │
└─────────────────────────────────────────┘
```

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 活动数量多时加载慢 | 可考虑分页，初期先用全量加载 |
| 时间判断依赖客户端时区 | 使用服务端返回的 UTC 时间，前端转换为本地时间 |
