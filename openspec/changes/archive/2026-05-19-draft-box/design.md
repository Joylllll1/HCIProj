## Context

用户需要一个草稿箱功能来保存未发布的帖子。ComposePage 已有"保存草稿"按钮但未实现。

**当前状态：**
- 后端：Post 模型已存在，createPost API 正常
- 前端：ComposePage 可填写 title、content、moodType、tags、image
- 后端尚无 Draft 模型和 API

**约束：**
- 使用 JWT + HTTP-only Cookie 认证
- 每个用户最多 10 篇草稿
- 草稿永不过期

## Goals / Non-Goals

**Goals：**
- 用户可将未发布的内容保存为草稿
- 用户可在草稿箱查看、编辑、删除草稿
- 发布草稿后自动删除该草稿
- 提供多入口访问草稿箱

**Non-Goals：**
- 草稿自动过期
- 跨设备同步（暂不支持）
- 草稿评论或点赞
- 草稿分享

## Decisions

### 1. Draft 数据模型

**方案：** 新建独立的 Draft 模型，不复用 Post 模型

**理由：**
- Draft 和 Post 生命周期不同（草稿 vs 已发布）
- Draft 不需要 likes、comments、saves 等发布后才有的字段
- 分离后查询性能更好

**Draft Schema：**
```javascript
{
  ownerUserId: ObjectId,      // 所属用户
  title: String,              // 标题（可选）
  content: String,            // 内容
  moodType: String,           // 心情类型
  mood: String,               // 心情标签
  tags: [String],             // 话题标签
  image: String,              // 图片 URL
  createdAt: Date,
  updatedAt: Date
}
```

### 2. API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/drafts | 创建草稿 |
| GET | /api/drafts | 获取用户所有草稿 |
| GET | /api/drafts/:id | 获取单个草稿 |
| PUT | /api/drafts/:id | 更新草稿 |
| DELETE | /api/drafts/:id | 删除草稿 |
| POST | /api/drafts/:id/publish | 发布草稿 |

### 3. 前端路由

- 新增 `drafts` 页面路由（独立页面）
- ComposePage 通过 URL 参数区分新建/编辑：`/compose?draftId=xxx`

### 4. 入口设计

| 位置 | 形式 |
|------|------|
| 侧边栏 | 新增"草稿箱"按钮，在"校园公告"下方 |
| ComposePage 右上角 | 草稿箱图标按钮 |

### 5. 发布后删除草稿

**流程：**
1. 用户点击"发布动态"
2. 调用 `POST /api/drafts/:id/publish`
3. 后端原子操作：创建 Post + 删除 Draft
4. 返回新 Post 的 id
5. 前端跳转详情页

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 用户存满 10 篇草稿后无法继续保存 | 草稿箱页面显示提示，引导用户清理或发布 |
| 发布失败但草稿已删除 | 后端使用事务确保原子性，或发布前先创建 Post 再删除 Draft |
| 草稿过多影响体验 | 限制 10 篇 + 支持批量删除 |

## UI Design

### 入口位置

#### 侧边栏入口
在"校园公告"（第3项）下方添加"草稿箱"按钮：
```
1. 动态首页
2. 热门话题
3. 校园公告
4. 草稿箱    ← 新增
5. 我的喜爱
6. 我的收藏
```

#### ComposePage 右上角（新发帖页面）

在"发布新动态"标题右侧（页面右上角）放置按钮：

```
发布新动态                              [草稿箱] [发布动态]
```

### 编辑草稿页面（ComposePage）

从草稿箱点击条目后，跳转到 ComposePage，预填草稿内容：

```

保存于 2026/05/12 14:30

[标题输入框]
[内容输入框]
[图片预览]   [话题标签]   [心情选择]

                              [保存草稿] [发布动态]
```

**布局说明：**
- 页面右上角：草稿箱按钮（跳转草稿箱），与"发布新动态"标题齐平
- 页面标题下方显示"保存于 xxx"
- 表单预填草稿的 title、content、moodType、tags、image
- 底部按钮布局与发布新动态页面一致："保存草稿"（更新草稿）+ "发布动态"（发布后删除草稿）
