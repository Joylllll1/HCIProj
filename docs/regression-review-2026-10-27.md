# 后续回归复查（2026-10-27）

这轮复查接续 [业务排查](bug-audit-2026-10-26.md) 和 [图片存储](image-storage.md)，重点确认此前修改是否改变原有设计，以及异步操作交错时是否会丢失内容。

## 原有设计与用户选择

- 保留 SSE 实时同步和通知轮询兜底；未改成纯轮询。
- 保留即时点赞反馈，以及“我的喜爱”中暂存取消点赞、离开或切换时提交的行为。
- 管理员仍可选择以普通身份或官方身份评论、回复；普通用户不能伪造官方标记。此前强制管理员使用官方身份的改动已纠正。
- 发帖的 `campus` 是已有业务字段，白名单继续接收它，省略时沿用模型默认校区；作者、删除状态和互动计数由服务端决定。
- 用户已确认 AI 停止后保留问题和部分回答；生成期间允许切换查看其他会话，回复属于原会话。这两项属于产品选择，不把原来的清理或锁定策略称为 bug。

## 验证范围

回归测试覆盖请求返回顺序、失败、账号重置、保存与历史事件交错。权限字段及异步状态修改另经独立代码复查。

最终工作树检查：前端 `npm run lint`、`npm test`、`npm run build` 全部通过（39 个测试文件、248 项测试）；后端 `npm run lint`、`npm test` 通过（79 项测试）；`git diff --check` 通过。

按用户要求拆分功能提交时，每笔代码提交先导出暂存区的完整快照，在隔离目录运行所在端的 lint 与测试，前端同时构建。检查不依赖工作区尚未提交的实现；文档最后随最终实现更新。此过程中额外捕获并修复了喜爱列表首次加载更多的时序问题。

真实 Chrome 已验证连续两次后退时的取消、放弃与保存：取消后网址和编辑页均留在 `/compose`，其余两种到达最后选择的首页；保存期间后退也能先恢复历史位置，再去原先确认的草稿箱，之后继续后退正常。浏览器覆盖了测试环境没有默认模拟的情况：第二次后退会取消已排队的恢复操作，必须按实际位置重新恢复。

浏览器还验证了同帖快速点赞／取消的即时反馈、同帖请求不重叠且最终与受控接口一致；首次点赞失败且用户已取消时不会再发一次错误操作；通知写入完成后能纠正期间返回的旧未读快照；重新生成同步失败仍更新正确回答，保留后续中断内容。

AI 使用 1440px 桌面及 390px 手机视口验证：A 生成时切换查看 B、切回 A 查看进度、在 B 完成后回看 A、最终同步失败后保留 A 的完整回答、停止后保留 A 的原问题和部分回答、后台重新生成同步失败，以及直接在 B 停止 A。长标题场景停止按钮约 91×40px，未越出手机面板；历史读取失败时列表会关闭，可直接查看缓存内容。临时脚本、受控响应日志与截图保存在忽略目录 `output/playwright/regression-*`。

浏览器使用隔离演示数据与受控 HTTP/SSE 响应，后端测试使用模型替身。真实 MongoDB、邮件和外部模型的完整端到端链路仍未验收；测试通过不能保证不存在遗漏。
