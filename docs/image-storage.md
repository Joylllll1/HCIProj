# 图片存储

图片文件独立存入后端目录，MongoDB 保存内部引用。帖子、草稿、评论、回复、活动及相关管理/喜爱接口返回同源 `/api/media/...` 地址，内容 JSON 和 SSE 不再重复携带 base64 原图。前端继续按原有方式选择、压缩、预览图片，保存时由后端转存。

## 目录与部署

默认目录为 `backend/storage/images/`，已被 Git 忽略。可在后端环境中设置绝对路径：

```dotenv
IMAGE_STORAGE_DIR=/var/lib/treehole/images
```

运行后端的用户需要该目录的读写权限。容器部署应将其挂载到持久卷；迁移机器或备份时必须同时保存 MongoDB 和图片目录。仅复制数据库无法恢复已经外置的图片字节。

当前实现适用于本地文件存储。多实例部署需要共享持久目录或后续接入对象存储。

## 读取与权限

| 图片 | 地址 | 读取条件 |
| --- | --- | --- |
| 帖子 | `/api/media/posts/:id/:index` | 帖子存在且未删除 |
| 草稿 | `/api/media/drafts/:id/:index` | 已登录且为该草稿作者 |
| 评论 | `/api/media/comments/:id` | 评论及父帖均有效 |
| 回复 | `/api/media/replies/:commentId/:replyId` | 回复、父评论及父帖均有效 |
| 活动海报 | `/api/media/events/:id` | 已通过或已归档的活动公开；其他状态仅申请者或管理员 |

地址含基于图片内容和所在位置生成的版本参数，修改或重排后可重新取图；相同旧图片迁移到文件后，版本地址保持稳定。二进制响应使用 ETag、按 Cookie 区分的私有缓存及正确的图片 Content-Type。权限检查在条件请求返回304之前执行。媒体响应附带 nosniff 和 sandbox CSP，限制 SVG 被单独打开时的活动内容。

服务端仍验证最多9张、单张3MiB、合计8MiB的原有编码大小限制。草稿详情返回与图片一一对应的 `imageBytes`，完整编辑器据此合并新选图片的大小；保存后会将临时 base64 替换成服务端地址，并保留保存期间继续输入或移除图片的操作。

## 旧数据兼容与迁移

已有 MongoDB base64 图片可继续通过媒体接口显示，旧草稿也能编辑和发布。内容列表只返回地址；旧字节仍在数据库中，迁移后才会转成文件引用。

迁移前先备份数据库，并确认图片目录已设为持久目录。默认命令只统计：

```bash
npm --prefix backend run migrate:images -- --dry-run
```

确认数据库和目录配置后执行转存：

```bash
npm --prefix backend run migrate:images -- --write
```

命令覆盖帖子/草稿的历史单图与多图、评论/回复图片、活动海报。每条记录先写好图片文件，再通过匹配原图片字段的条件更新数据库；若读取后图片发生变化，该记录会计入 `skipped`，可稍后重新运行。迁移保留正文和时间字段，相同字节会复用文件；中途失败时已完成的记录仍有效，可修正问题后重跑。

本轮验证没有对用户真实数据库执行迁移。

## 保留的后续事项

上传配额、统一限流、独立缩略图、对象存储和无引用文件清理仍列在后续规划。删除帖子或草稿暂不立即删除文件，以免误删其他内容复用的图片。此存储改动保留原有 SSE、点赞提交时机和匿名展示方式。

## 验证记录（2026-10-26）

前端38个测试文件 / 221项测试、后端79项测试、两端lint、前端构建与diff检查通过。权限、缓存隔离、文件原子写入、SVG响应头及旧数据迁移经过独立复查。

浏览器通过真实HTTP接口和临时文件目录验证了本地PNG选择、保存、草稿列表摘要、重开继续编辑、发布后显示，以及390px下的大图查看。图片返回二进制和ETag，条件请求得到304；换用另一个账号后，同一已缓存草稿图片地址返回404。旧base64帖子和草稿能正常解码；旧草稿保存后转成文件引用，图片版本地址保持稳定。测试中的数据库使用内存模型替身，未连接或迁移用户真实MongoDB。

临时浏览器脚本与截图位于被Git忽略的 `output/playwright/image-storage-*`。迁移服务另有默认只统计、各内容类型字节保留及并发编辑条件更新的回归测试。
