# ADR-003：使用 Zustand 作为前端状态管理

## 状态
已接受

## 背景
前端需要管理用户登录态、帖子列表、UI 状态等全局状态。团队对 React Hooks 有了解，但缺乏复杂状态管理库经验。项目规模中等，需轻量级、低学习成本的方案，符合"低压力表达"原则。

## 决策
使用 **Zustand** 作为前端全局状态管理方案。

## 理由
1. 轻量级——无 Redux 的大量样板代码
2. 学习成本低——API 简单直观，基于 React Hooks
3. 符合项目原则——"低压力表达"，不给团队增加学习负担
4. 功能足够——满足中等规模状态管理需求
5. 迁移平滑——可从 React Hooks 平滑迁移

## 后果
- 正面：开发效率高、代码简洁、性能良好
- 负面：超大规模应用不如 Redux（本项目不会遇到）、部分高级功能需中间件
- 风险：状态设计不合理可能导致混乱、需制定统一的状态管理规范
