# 真实前后端联调记录（2026-10-28）

本轮针对“修复是否破坏实际功能”进行联调。使用项目当前代码的独立副本、Node.js 20.20.2、MongoDB 8.0.24、真实 Express 与 Mongoose，以及浏览器中的 React 前端。未启用 `preview=1`，未替换业务接口或数据库模型。

数据库、图片目录和测试账号均独立创建；正常运行的数据库与 `.env` 未用于本轮测试。AI 后端连接本地受控模型接口，验证流、中断与持久化，不验证外部模型供应商的可用性或回答质量。

## 已实际通过的链路

| 流程 | 验证结果 |
| --- | --- |
| 登录、退出与刷新 | 真实登录返回 HttpOnly Cookie；删除 access Cookie 后，受保护请求返回 401，刷新接口成功后重放。退出并换账号后，“我的帖子”列表、草稿和 AI 历史切换到新账号。 |
| 图片草稿与发布 | 从电脑文件选择器上传图片，保存草稿、刷新恢复、继续修改、通过离开确认保存、重新打开并发布；帖子与图片可以再次读取。 |
| 评论、回复与实时同步 | 两个独立浏览器账号操作；另一方无需刷新即可看到新评论和回复，通知中心收到实际通知记录。 |
| 点赞与收藏 | 浏览器实际点赞；创建收藏夹、保存帖子并刷新恢复。HTTP 检查另验证帖子、评论和回复的点赞／取消及 MongoDB 中的最终计数。 |
| 权限与删除 | 普通用户不能伪造官方身份，管理员可自行选择；已删除父帖的评论、点赞、举报和图片读取被拒绝。管理员删除产生真实 SSE 与更新后的计数。 |
| 图片存储 | MongoDB 保存文件引用，临时目录中的图片字节可读取；接口返回同源图片 URL，ETag 与草稿所有者权限检查正常。旧 base64 图片仍可读取。迁移命令默认 dry-run，未执行写入迁移。 |
| 活动海报 | 待审核海报仅申请者与管理员可读；审核通过后可公开读取，删除后缓存请求也不能绕过权限。 |
| AI 会话 | A 生成时查看 B，完成回答仍保存在 A；从 B 停止 A 后，原问题与部分回答以中断状态存入 MongoDB，浏览器刷新后仍存在。 |

后端真实 HTTP／MongoDB 检查共 13 项通过；浏览器流程覆盖桌面与 390px 手机视口。账号及业务数据均为本轮生成的测试数据。

## 联调发现并修复的计数问题

回复后曾出现“数据库和评论区 3 条，帖子顶部 4 条”。原有本地增减计数与 SSE 的绝对计数同时返回，会重复加减。

- 后端先广播评论／回复变更，再广播权威计数，保持同一 SSE 连接上的顺序。
- 前端根据稳定 ID 避免接口完成时重复处理已同步的增删，保留无 SSE 时的本地反馈。
- 成功加载完整评论后，按合并实时变更后的评论与回复同步计数；首页首次加载期间也接收对应变更，避免旧 GET 覆盖新事件。

真实浏览器复验的计数序列为 `0 → 1 → 2 → 3 → 2 → 0`：新增评论、两条回复、删除一条回复、删除含剩余回复的父评论。每一步数据库、帖子顶部、评论区均一致，刷新后仍为 0。另有异步回归覆盖 HTTP、GET 和 SSE 不同返回顺序，修复经过独立复查。

## 补充：大图预览被裁切

真实上传的 `1075 × 1075` 图片在 `1440 × 900` 浏览器窗口中，初始预览曾以原始高度显示在仅 `746px` 高的区域内，底部被裁切。预览网格的自动轨道被图片的固有尺寸撑开；显式将行列约束为 `minmax(0, 1fr)` 后，图片按比例缩为 `746 × 746`，完整留在可视区域。

浏览器复验覆盖两张真实上传图片、放大后滚动、恢复适合屏幕、按钮／缩略图／方向键切换、Escape 关闭与再次打开，以及 `390 × 844` 和 `844 × 390` 窗口。另用仅在浏览器拦截层生效的长图、宽图检验不同宽高比，没有修改帖子或存储文件。相关图片组件的 13 项单元测试通过；实际布局由浏览器尺寸断言验证。

## 补充：确认搜索意外返回首页

顶部搜索原先在所有非首页页面确认时均导航至首页，导致“我的喜爱”“我的收藏”“校园公告”已有的页面内搜索无法正常使用。现在这三页的 Enter、搜索按钮与历史记录选择均留在当前页，输入框提示和无障碍名称说明搜索范围，也不再请求首页滚动。首页继续搜索全部树洞；设置、详情等未提供页面内筛选的页面保留全站搜索入口。

真实浏览器分别验证三页的 Enter、按钮和历史记录，喜爱／收藏能筛选出对应测试帖子，公告的无匹配结果仍留在公告页；手机搜索按钮也保持当前页。另验证首页实际发出成功的搜索请求，以及从设置页进入首页全站搜索。新增 5 项回归测试，顶部栏测试共 11 项通过。

## 补充：完整编辑器的图片布局与预览

完整编辑器仍存在一条旧规则，将所有待发布图片限制为 `200px` 高并按 `cover` 裁切；单图的“继续添加”方格还会单独占据 `540 × 540` 的区域。删除按钮虽定位在图片容器内，但图片被裁切并居中后，按钮与画面分离。原先使用普通 `img`，也没有接入点击预览。

现已移除相互冲突的旧规则，图片与添加入口使用同尺寸网格，桌面三列、手机两列，缩略图完整包含图片，删除按钮固定在各自缩略图右上角。复用现有 `ClickableImage`，支持打开所选图片、切图、关闭后继续编辑，以及保存草稿后从同源媒体地址再次预览。

使用用户提供的方图，通过真实文件选择器上传；另生成并实际上传 `600 × 6000` PNG，顶部和底部使用不同颜色作为定位标记。浏览器验证桌面与手机完整适配、放大后滚动到 6000px 长图的底部，以及保存、刷新、重新打开草稿后尺寸仍为 `600 × 6000`。另覆盖单图、两图、九图上限和删除后重新排列；删除缩略图不会打开预览或发出保存／发布请求。新增 3 项回归，编辑器测试共 19 项通过。
